## 1. Контекст

Необходимо разработать варианты MVP-решений для мониторинга свиноводческих ферм, который работает в соответствии с указанными ниже требованиями на нескольких фермах.

## 3. Решение

Так как в заданиях 1-4 платформа разрабатывается для самой компании - можно использовать уже имеющийся у нее BI-модуль для агрегации и визуализации метрик. В рамках MVP и того, что явно это не обговорено, считается, что у него есть HTTPS интерфейс, способный получать метрики из внешних источников. До доработки этим интерфейсом мог пользоваться "Аналитик", работающий с BI-системой.

Диаграмма C1 представлена в C1_solution.puml

Система разделяется на:
- Центральную Платформу (1 экземпляр)
- N Edge-агентов (по одному на ферму)

Edge-агенты разворачиваются на локальной инфраструктуре фермы (baremetal или локальная VM).  
Платформа размещается в облачной инфраструктуре.

Причины разделения:

- Автономность (R2)
	Ферма продолжает функционировать при потере связи с платформой.
	Edge-агент:
	- хранит локальные данные; после восстановления связи выполняется синхронизация с Платформой(R3)
	- управляет оборудованием
	- отправляет локальные уведомления (R4)
	Данные между платформой и Edge синхронизируются асинхронно

- Производительность (P2)
	Видеоанализ выполняется на ферме:
	- снижение сетевого трафика
	- снижение задержек
	- уменьшение нагрузки на облако

- Масштабируемость
	Архитектура 1 + N позволяет:
	- прозрачно добавлять новые фермы
	- масштабировать Edge горизонтально
	- не изменять центральную платформу

- Независимость компонентов 
	Edge и Платформа взаимодействуют через HTTP API.
	- Нет прямых зависимостей на уровне реализации
	- Компоненты могут обновляться независимо(S1)
	- Контрактное взаимодействие

- Централизация безопасности
	Аутентификация и авторизация выполняются через Платформу:
	- единая точка входа
	- централизованный контроль доступа
	- аудит действий пользователей

-  Централизация мониторинга (S2)
	Логи и агрегированные метрики передаются на Платформу.
	Используется существующий BI-модуль компании.

## <a name="_bjrr7veeh80c"></a>**4. Альтернативы**

### 4.1 Централизованная архитектура без Edge

Диаграмма C1 представлена в C1_alter.puml

Платформа разворачивается в облаке и фермы подключаются  к ней

**Преимущества**

- Упрощение эксплуатации
	- Нет локального сервера
	- Нет обновлений на фермах
	- Нет удалённого администрирования
	- Нет синхронизации между узлами
	
- Централизация логики
	- Вся бизнес-логика в одном месте
	- Нет риска рассинхронизации версий
	- Проще CI/CD Платформы

- Ускорение интеграции Платформы
	- Нет разработки edge-контуров
	- Нет offline-режима
	- Нет сложной синхронизации

**Недостатки, ограничения, риски**

- Возможна потеря автономности (нарушение R2-R4)
	При потере сети:
	- Нет управления оборудованием
	- Нет локальных алертов
	- Нет видеоанализа
	- Нет записи телеметрии
- Анализ видео на стороне Платформы
	- Снижение производительности анализа для клиента (нарушение P2)
	- Высокая нагрузка на сеть и диск из-за загрузки видео с каждой камеры на облако Платформы
- При масштабировании количества ферм нагрузка на платформу вырастает пропорционально количеству новых камер
